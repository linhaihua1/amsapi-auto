## 二、运行测试

### 2.1 入口说明

框架有两个等价入口：

| 入口 | 特点 | 适用 |
| --- | --- | --- |
| `python main.py` | 打印运行摘要，跑完自动渲染 Allure HTML | **日常推荐** |
| `pytest` | 原生，参数最全 | 调试、精细筛选 |

两者共用同一份 `pytest.ini` 与 `testcase/conftest.py`，行为一致。
`main.py` 只是把常用参数（报告类型）封装了一下。

### 2.2 main.py 参数

```
python main.py [--smoke] [--report allure|html|both|none] [其它 pytest 参数...]
```

- `--smoke` 开启冒烟模式，只执行带 `smoke` 标签的用例（详见 [第十节](#十cicd-集成)）
- `--report` 之外的参数**原样透传给 pytest**，所以 pytest 的用法都能用
- `--report` 不传时，取 `config/conf.ini` 里 `[report] report_type` 的值

```bash
# 组合使用：只跑 Excel 且不生成报告
python main.py -m excel --report none

# 跑单个文件、只看失败用例
python main.py testcase/test_login.py --lf   # --lf = last failed
```

### 2.3 用例筛选

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| 按 marker | `-m excel` | 按数据源/类别筛选 |
| 按名称 | `-k login` | 匹配用例名（支持 `not` / `and` / `or`） |
| 按用例编号 | `-k id1001` | **推荐**：两种数据源都适用（Excel/YAML 的用例 id 都以 `id<编号>` 开头） |
| 按文件 | `testcase/test_login.py` | 指定路径 |
| 按类 | `-k TestLoginFlow` | 匹配类名 |
| 只跑上次失败 | `--lf` | last failed |
| 失败即停 | `-x` | 第一个失败就停，调试用 |

> **`-k` 的关键字请用 ASCII**。pytest 会把用例 id 里的非 ASCII 字符转义成 `\uXXXX`，
> 所以 `python main.py -k 登录` 会**静默选中 0 条用例**（不报错、退出码 5）。
> 按用例编号筛（`-k id1001`）或用标签 `-m` / `--smoke` 才是可靠做法。
| 重跑失败 | `--reruns 2` | 需装 `pytest-rerunfailures` |

**可用 marker**：

| marker | 含义 |
| --- | --- |
| `smoke` | 冒烟用例（CI/CD 构建后快速验证） |
| `excel` | Excel 数据驱动用例 |
| `yaml` | YAML 数据驱动用例 |
| `mysql` | MySQL 数据驱动用例 |
| `network` | 依赖真实服务环境的用例 |

```bash
# 排除依赖真实环境的用例（无内网环境时常用）
python main.py -m "not network"

# 组合：只跑 YAML 且排除真实环境
python main.py -m "yaml and not network"
```

### 2.4 三种数据驱动的执行特性

三种驱动**执行入口完全一致**（都走 `BaseApi.run_case` / `request`），差别只在数据来源：

| 驱动 | 文件 | 何时执行 | 地址拼接 | 结果回写 |
| --- | --- | --- | --- | --- |
| Excel | `testcase/test_excel_driver.py` | 始终执行 | 用例写完整 url，或拼 `base_url` | 写回 Excel 的 time/response/ispass |
| YAML | `testcase/test_yaml_driver.py` | 始终执行 | 同上 | 不回写 |
| MySQL | `testcase/test_sql_driver.py` | 仅 `data_source = mysql` | `配置域名 + : + port_num + url` | 写 `test_result_record` 表 |

> Excel / YAML 驱动读取不到可执行用例时，整个模块**自动跳过**（不会报错），
> 这是设计行为，不是 bug。

### 2.5 框架单元测试（离线自检）

上面跑的都是**业务用例**（要连被测环境）。框架自身还有一套**单元测试**，
离线运行、不依赖任何服务、约 10 秒跑完：

```bash
python -m pytest tests              # 全部框架自测
python -m pytest tests -q           # 简洁输出
python -m pytest tests/test_common_base.py     # 只跑某个模块
python -m pytest tests -x --tb=long            # 失败即停 + 完整堆栈
python -m flake8 .                  # 静态检查（提交前必跑，CI 门禁）
python tools/preflight.py           # 环境预检（依赖 / 配置 / 数据 / 目录 / 连通性）
```

**什么时候需要它**：

| 场景 | 为什么 |
| --- | --- |
| 改了 `api/` `common/` `utils/` `config/` `main.py` | 确认没把框架改坏 |
| 拉取别人的改动后 | 本地快速验证，不必连内网 |
| 内网环境不可用时 | 唯一能跑的验证手段 |
| CI 流水线最开始 | 框架坏了就没必要跑接口测试 |
| **跑接口用例报「环境问题」前** | 先 `preflight` 排除依赖缺失 / 配置未填 / 目标不通 |

带覆盖率：

```bash
python -m pytest tests \
  --cov=api --cov=common --cov=config --cov=utils --cov=tools --cov=main --cov=testcase \
  --cov-report=html:report/unit-coverage
```

> 单元测试**不会**修改 `data/` 下的任何数据文件，也不会产出接口测试报告。
> 详细说明见 [07-单元测试](07-单元测试.md)。

### 2.6 不连内网也能跑通（离线体验）

> **这一节是为「拿不到被测系统」的人写的。**
> 框架自带一个本地 mock 服务，把接口在你自己机器上复刻出来，
> 因此**不连内网、不连外网**也能把整条链路（请求 → 关联 → 断言 → 报告）走完整。

#### 第 0 步：装依赖

```bash
python --version                          # 建议 3.8 及以上
python -m pip install -r requirements.txt
```

#### 第 1 步：起本地 mock 服务（终端 A）

```bash
python tools/mock_server.py
```

输出：

```
本地 mock 服务已启动：http://127.0.0.1:18080
可用接口：
    /admin/org/getTreeRootParentCodePage
    /admin/resource/authority
    /api/v1/datasource/list
    ...
```

**保持这个终端开着**（`Ctrl + C` 停止）。它默认只绑 `127.0.0.1`，局域网内其它机器访问不到。

#### 第 2 步：跑 YAML 示例用例（终端 B）

```bash
AMSAPI_BASE_URL=http://127.0.0.1:18080 AMSAPI_DATA_SOURCE=yaml python main.py
```

预期结果：

```
===================== 3 passed, 2 skipped =====================
```

**Windows PowerShell 的写法**（`$env:` 设置环境变量，不是 `VAR=x` 前缀）：

```powershell
$env:AMSAPI_BASE_URL="http://127.0.0.1:18080"
$env:AMSAPI_DATA_SOURCE="yaml"
python main.py
```

#### 第 3 步：跑 Excel 示例用例

```bash
AMSAPI_BASE_URL=http://127.0.0.1:18080 python main.py -m excel
```

预期结果：

```
===================== 4 passed, 2 skipped =====================
```

> `skipped` 里有 1 条是**故意为之**：Excel 第 5 行演示 `depends`
> 依赖了一条不存在的用例，于是它被「跳过」而不是「失败」。
> 这正是「前置没成功 ≠ 本用例实现有问题」的处理方式。

#### 第 4 步：把报告链路走完整

```bash
AMSAPI_BASE_URL=http://127.0.0.1:18080 AMSAPI_DATA_SOURCE=yaml python main.py --report allure
python tools/generate_report.py --open
```

报告打开后**重点看这三处**（这是理解框架最快的方式）：

| 位置 | 看什么 |
| --- | --- |
| 右上角「环境」页 | 本次生效的系统档案、判定风格、业务码路径、认证方式、超时 |
| 某条用例的步骤树 | 「执行接口请求与断言」下面的 `请求信息` / `响应信息` / `响应体` 三个附件 |
| `admin.yaml` 那两条用例 | 请求头里的 `access-ticket` 已经不是 `${ticket}`，说明**参数关联**生效了 |

#### 第 5 步（可选）：换一种系统再试一遍

`examples/` 目录下还有商城、数据中台、老系统（XML/GBK/签名）三套示例，
命令一行都不用改框架代码，只换档案与环境变量：

```bash
# 商城（success 判定 + Bearer）
AMSAPI_SYSTEM=mall AMSAPI_BASE_URL=http://127.0.0.1:18080 \
AMSAPI_DATA_SOURCE=yaml AMSAPI_CASES_DIR=examples/mall/cases python main.py -m yaml
```

完整三条命令与解释见 [`examples/README.md`](../examples/README.md)。

#### 这一节验证了框架的哪些能力

| 能力 | 体现在哪 |
| --- | --- |
| 请求发送与响应解析 | 所有用例 |
| 接口间参数关联 | `login.yaml` 提取 `ticket` → `admin.yaml` 用 `${ticket}` |
| 业务码判定 | 档案 `response.style` 决定看哪个字段 |
| 字段级断言 | 用例 `expects` 字段（`gt:` / `type:` / `not_empty:` / `elapsed=`…） |
| 用例依赖 | Excel 第 5 行的 `depends: 99` → 跳过 |
| 数据驱动 | 同一批接口，Excel 与 YAML 两种数据源都能跑 |
| 报告与日志 | Allure 步骤树、附件、环境页；`log/YYYY_MM_DD.log` |

#### 关于示例数据的三个说明

1. **示例用例的 url 都是相对路径**（如 `/v1/users/login`），
   真实域名由 `AMSAPI_BASE_URL` 或系统档案提供 —— 因此同一份用例可在测试 / 预发 / 生产之间切换。
2. **示例数据不是真实业务数据**。仓库里不预置任何真实地址、账号、密码、密钥；
   `data/api_tables.xlsx` 与 `data/cases/*.yaml` 都是通用示例。
3. **换成自己的系统时**：把用例 url 改成自己的接口，把账号密码放进
   `conf.ini` 或环境变量（不要写进用例文件），再按
   [08-系统适配指南](08-系统适配指南.md) 写一份系统档案即可。

> 仓库里还有一套自动化检查守这条线：`tests/test_repo_sanitized.py`
> 会扫描全仓文件，一旦有人误把真实地址 / 账号 / 口令提交进来就会立刻失败。

## 三、切换环境

### 3.1 改全局域名（推荐）

如果所有用例都属同一域名，在 `config/conf.ini` 里配置，用例只写相对路径：

```ini
[env]
env = test
base_url = http://192.0.2.10:9050
```

此时用例 url 写 `/v1/users/login` 即可，框架自动拼接成
`http://192.0.2.10:9050/v1/users/login`。

**注意**：若用例 url 本身是完整地址（以 `http://` / `https://` 开头），
则**不会被 base_url 覆盖**，仍按用例自带的地址请求。

### 3.2 改超时与证书校验

```ini
[run]
timeout = 10        ; 请求超时（秒）
verify = false      ; https 证书校验，内网自签证书场景保持 false
```

### 3.3 环境标识

```ini
[env]
env = test          ; 仅用于日志与报告「环境」页展示，不影响请求
```

建议切换环境时同步修改此项，便于从报告上区分是哪次环境的执行结果。

### 3.4 切换被测系统（系统适配档案）

接**另一个 web 系统**时（政务 → 商城、财务 → 中台……），改这一项即可，
**用例数据一行都不用动**：

```ini
[env]
system = mall       ; 对应 config/systems/mall.ini
```

或运行时临时指定（优先级更高，CI 常用）：

```bash
AMSAPI_SYSTEM=mall python main.py --smoke
```

现成档案：

| 档案名 | 面向系统 | 成功判定 | 认证 |
| --- | --- | --- | --- |
| `default` | 内置默认（等价改造前行为） | `body.status` | 无 |
| `gov` | 党政 / 政务 | `body.status` | 自定义头 `access-ticket` |
| `finance_erp` | 财务 / ERP | `body.code` | Cookie + 签名钩子 |
| `mall` | 商城 / 购物 | `body.success` | `Bearer` + 多域名 |
| `dataplatform` | 数据中台 / 信息系统 | `body.code == 0` | `OAuth2` 自动取令牌 |

档案名写错会直接报错并列出可用档案，不会静默用错规则。

**进哪个系统就用哪份档案**，同一套框架可以在多个系统之间来回切，互不影响。

日志开头与 Allure 报告的「环境」页会打印本次生效的适配信息
（判定风格 / 业务码路径 / 认证方式 / 域名别名 / 钩子），便于确认：

```
系统档案 : mall
系统名称 : 商城/购物
主域名   : https://api.example.com
判定风格 : success
成功值集合: true,1,yes,ok
认证方式 : bearer
```

**完整字段说明、五类系统的接入示例、常见差异速查表见
[08-系统适配指南](08-系统适配指南.md)。**

### 3.5 其它可配置项（日志 / 脱敏 / 网络 / 报告 / 认证 / CI 判定）

框架里**没有任何硬编码的业务数据**：所有可变项都集中在 `config/conf.ini`
（或环境变量）里。除上面几节讲过的，还有这几组：

```ini
[report]
report_type = allure          ; allure | html | both | none
title = 接口自动化测试         ; 报告标题（Allure 环境页 + pytest-html 标题）
project = amsapi-auto         ; 项目名（Allure 环境页）
html_name = report.html       ; pytest-html 文件名
max_attach_len = 20000        ; Allure 单条附件最大字符数（超出截断）

[log]
level = DEBUG                 ; 见第七节（含轮转与保留天数）

[mask]
mode = partial                ; partial = 保留首尾少量字符 | full = 全遮蔽
keep_prefix = 3               ; partial 模式保留前缀字符数
keep_suffix = 2               ; partial 模式保留后缀字符数
extra_keys =                  ; 追加敏感字段名（逗号分隔），如 mobile,idcard

[network]
trust_env = true              ; 是否沿用系统代理（HTTP_PROXY / HTTPS_PROXY）
auto_bypass_proxy = true      ; 内网/环回地址自动绕过代理（必须保持 true）
bypass_hosts =                ; 额外不走代理的主机，如 corp.internal,10.

[auth]
refresh_ahead = 60            ; OAuth2 令牌到期前多少秒提前续期
token_timeout = 10            ; 取令牌请求超时（秒）
token_verify = false          ; 取令牌是否校验 https 证书

[ci]
detect_env_vars = JENKINS_URL,JENKINS_HOME,GITLAB_CI,BUILD_NUMBER,GITHUB_ACTIONS,TF_BUILD,CI
                              ; 出现任一变量即判定为 CI，自动跳过本地 HTML 渲染
```

对应的环境变量：`AMSAPI_REPORT_TITLE` / `AMSAPI_REPORT_PROJECT` /
`AMSAPI_REPORT_HTML_NAME` / `AMSAPI_ALLURE_MAX_ATTACH_LEN` /
`AMSAPI_LOG_LEVEL` / `AMSAPI_LOG_CONSOLE_LEVEL` / `AMSAPI_LOG_MAX_BYTES` / `AMSAPI_LOG_KEEP_DAYS` /
`AMSAPI_MASK_SENSITIVE` / `AMSAPI_MASK_MODE` / `AMSAPI_MASK_EXTRA_KEYS` /
`AMSAPI_TRUST_ENV` / `AMSAPI_AUTO_BYPASS_PROXY` / `AMSAPI_BYPASS_HOSTS` /
`AMSAPI_OAUTH2_REFRESH_AHEAD` / `AMSAPI_OAUTH2_TOKEN_TIMEOUT` / `AMSAPI_OAUTH2_TOKEN_VERIFY`。

> **脱敏（`[mask]`）**：日志与 Allure 附件在**写入前**统一打码，覆盖
> `password` / `token` / `ticket` / `authorization` / `secret` / `sign` / `cookie` 等字段名。
> 日志与报告会随构建制品归档、被转发，**默认必须保持开启**；仅本地反复调试时可临时
> `AMSAPI_MASK_SENSITIVE=false`，切勿落到仓库或 CI 制品里。
>
> **网络（`[network]`）**：办公网 / CI 机器通常配置了「出公网」代理。若被测系统在内网，
> 请求会被代理拦截并报出**指不到根因的 502**。`auto_bypass_proxy = true` 会对
> 环回（`127.0.0.1` / `localhost` / `::1`）、私网（`10.` / `172.16-31.` / `192.168.`）、
> `*.local` / `*.internal` / `*.corp` 等自动绕过代理；确有其它主机需绕过时写进 `bypass_hosts`。

> **一条通用规律**：档案（`config/systems/*.ini`）里的**每一项**都能被环境变量覆盖，
> 命名规则是 `AMSAPI_<段名>_<字段名大写>`：
>
> | 想覆盖 | 环境变量 |
> | --- | --- |
> | `[env] encoding = gbk` | `AMSAPI_ENCODING=utf-8` |
> | `[env] response_format = xml` | `AMSAPI_RESPONSE_FORMAT=json` |
> | `[hosts] admin = http://...` | `AMSAPI_HOST_ADMIN=https://...` |
> | `[auth] client_secret = ...` | `AMSAPI_AUTH_CLIENT_SECRET=...`（CI 凭据注入） |
> | `[hooks] before_request = ...` | `AMSAPI_HOOKS_BEFORE_REQUEST=...` |
>
> 因此「同一份档案跑三套环境」是完全可行的：档案放稳定属性，
> 差异（域名、密钥、编码）全部由流水线注入。

## 四、切换数据源

只改一行配置，用例逻辑完全不动——这是分层设计的核心收益。

```ini
[run]
data_source = excel     ; excel | yaml | mysql | all
```

| 数据源 | 适用场景 | 维护成本 |
| --- | --- | --- |
| `excel` | 业务同学维护、需要表格视图 | 低 |
| `yaml` | 开发维护、需要 diff 与版本管理 | 中 |
| `mysql` | 用例集中管理、多系统共用 | 高（需建表） |
| `all` | 同时跑 Excel 与 YAML 驱动（兼容早期行为） | — |

切换后：

```bash
python main.py              # 会按 data_source 执行对应驱动
python main.py -m yaml      # 也可用 marker 直接指定，覆盖 data_source
```

> `-m` / `-k` 一旦出现在命令行，`data_source` 就不再参与过滤（以命令行为准）；
> `data_source` 取值非法时会直接报错并列出可选值，不会静默按默认值跑。
> MySQL 未配置（`[db]` 段为空）时，SQL 驱动会以清晰文案**跳过**而非报失败。

### Excel 数据源附加配置

```ini
[run]
sheet_name = test_case_list     ; 用例所在 sheet 名
write_back = true               ; 是否回写执行结果（false 可加速，且不改动原文件）
```

见 [第九节 · MySQL 数据源](#九mysql-数据源)。

## 五、结果回写

| 数据源 | 回写位置 | 回写内容 | 开关 |
| --- | --- | --- | --- |
| Excel | `data/api_tables.xlsx` 对应行 | B 列 time、L 列 response、M 列 ispass | `run.write_back` |
| MySQL | `test_result_record` 表 | case_id、times、response、result | `run.write_back` |
| YAML | 不回写 | — | — |

> **回写时机**：结果先写入内存，Excel 驱动类执行完毕落盘一次，
> 整个会话结束时再统一落盘（`ExcelUtil.flush()`）。
> 这样既避免每条用例都存一次文件的性能损耗，又能保证中途异常不丢结果。

关闭回写：

```ini
[run]
write_back = false
```

**建议**：CI 环境设为 `false`，避免并发写入冲突与文件被改动。

## 六、测试报告

### 6.1 报告类型

| 类型 | 命令 | 产物 | 特点 |
| --- | --- | --- | --- |
| Allure | `--report allure` | `report/allure-report/index.html` | **推荐**，步骤树 + 附件 + 环境页 |
| pytest-html | `--report html` | `report/report.html` | 单文件，无需 Java/Allure，方便外发 |
| 两者都要 | `--report both` | 上述两个 | — |
| 不要报告 | `--report none` | — | 快速回归时用 |

### 6.2 Allure 报告怎么用

```bash
# 生成（跑完自动渲染，见 main.py）
python main.py --report allure

# 已跑完测试，只想重新渲染
python tools/generate_report.py

# 渲染并直接打开浏览器
python tools/generate_report.py --open

# 渲染前清空历史报告（推荐，避免残留旧数据）
python tools/generate_report.py --clean --open
```

> `--open` 会用 `allure open` 起一个本地服务。
> **不要直接双击 `index.html`**：Allure 报告通过 AJAX 加载数据，
> `file://` 协议会被浏览器安全策略拦截，会看到空白页。

### 6.3 报告结构解读

```
接口自动化（Epic）
├── Excel 数据驱动（Feature）
│   └── 用例列表（Story）
│       ├── id1 登录系统          ← 用例标题（动态拼接 id + title）
│       │   ├── 参数：用例id / 接口地址 / 请求方法 / 期望状态码
│       │   ├── 步骤：执行接口请求
│       │   │   ├── 附件：请求信息（方法/地址/头/参数/体）
│       │   │   └── 附件：响应信息 + 响应体
│       │   ├── 步骤：断言业务状态码 == 200
│       │   └── 步骤：回写执行结果到 Excel
│       └── id2 测试
├── YAML 数据驱动
├── MySQL 数据驱动
└── PO 风格用例
```

**报告右上角「环境」页**能看到：

| 分组 | 内容 |
| --- | --- |
| 生效配置 | 测试环境、数据源、是否回写、全局域名、超时、Allure 是否可用 |
| 系统适配 | 档案名、判定风格、业务码路径、认证方式、钩子（**不含任何凭证**） |
| **执行元数据** | 运行位置、Python 与关键依赖版本；git 提交与构建号**有则显示**（需处于 git 仓库 / CI） |
| 安全 | 敏感信息脱敏状态（开启 / 模式） |

**失败排查顺序**：步骤树 → 看是哪一步红的 → 展开"请求信息"/"响应体"附件 → 对比期望与实际。

> 附件里的口令、令牌是**打码后**的内容（`dem****rd` 之类）。需要看原文时，
> 本地用 `AMSAPI_MASK_SENSITIVE=false python main.py ...` 重跑一遍 ——
> **切勿把未脱敏的报告提交或上传到流水线制品**。

### 6.4 报告渲染前置条件

| 项 | 校验 | 未安装时 |
| --- | --- | --- |
| Java | `java -version` | allure generate 会失败 |
| Allure CLI | `allure --version` | 同上 |

安装 Allure CLI：

1. 下载 https://github.com/allure-framework/allure2/releases
2. 解压到任意目录（如 `D:\allure-2.29.0`）
3. 把 `bin` 目录加入系统 `PATH`
4. 重新打开终端，执行 `allure --version` 验证

> 未安装时**不影响测试执行与断言**，只是不渲染 HTML。
> 框架会打印提示 `[提示] Allure 报告渲染失败：...`，这是预期行为。

## 七、日志

| 项 | 说明 |
| --- | --- |
| 位置 | `log/YYYY_MM_DD.log`（按天切分，文件名格式可配） |
| 同时输出 | 控制台（受 pytest `-s` 影响） |
| 路径定义 | `config/settings.py` 的 `LOG_DIR`（可用 `AMSAPI_LOG_DIR` 重定向） |
| 级别 / 格式 / 文件名 | `config/conf.ini` 的 `[log]` 段，见 [3.5 其它可配置项](#35-其它可配置项日志--脱敏--网络--报告--认证--ci-判定) |
| **大小轮转** | 单个文件超过 `max_bytes` 自动切 `.1` / `.2` …，最多保留 `backup_count` 个 |
| **历史清理** | 启动时按 `keep_days` 清理更早的按天日志（**只删框架自己生成的文件**，`0` = 不清理） |
| **敏感信息脱敏** | `mask_sensitive = true` 时，口令 / 令牌 / 票据在**写入前**统一打码 |

`config/conf.ini`：

```ini
[log]
level = DEBUG            ; DEBUG | INFO | WARNING | ERROR
console_level = DEBUG    ; 控制台单独设级别，CI 里想少刷屏可设 INFO
file_name_format = %Y_%m_%d
format = %(asctime)s | %(levelname)-7s | %(filename)s:%(lineno)d | %(message)s
date_format = %Y-%m-%d %H:%M:%S
root_name = amsapi
mask_sensitive = true    ; 强烈建议保持 true（日志会随构建制品归档、被转发）
max_bytes = 20971520     ; 单文件上限 20MB，超出轮转；0 = 不限
backup_count = 5         ; 轮转备份个数
keep_days = 30           ; 历史日志保留 30 天；0 = 不清理
```

`[mask]` 段控制打码方式（`partial` 保留首尾少量字符便于比对，`full` 全遮蔽），
详见 [3.5 其它可配置项](#35-其它可配置项日志--脱敏--网络--报告--认证--ci-判定)。

```bash
# 临时把控制台日志调成 INFO，只看关键行
AMSAPI_LOG_CONSOLE_LEVEL=INFO python main.py

# 临时关闭脱敏（仅本地反复调试用，切勿落进仓库或 CI 制品）
AMSAPI_MASK_SENSITIVE=false python main.py
```

> **脱敏后的日志长这样**：`【关联】ticket = TK-****xu`、`password = dem****rd`。
> 判断「是不是同一个令牌」看保留的前后缀即可，完整值不再出现。

关键日志标记：

| 标记 | 含义 |
| --- | --- |
| `【请求】GET http://...` | 接口层发起请求 |
| `==> get http://...` | 请求工具层发送（更底层） |
| `<== 200 OK \| 123.4 ms` | 收到响应与耗时 |
| `【关联】ticket = xxx` | 关联提取成功，已写入变量池（值按 `[mask]` 打码） |
| `结果已回写 Excel：api_tables.xlsx` | 结果落盘 |
| `请求异常：GET http://... -> ...` | 网络层异常（超时/连接失败，含被代理拦截的 502） |
| `teardown 失败：...` | 用例清理（teardown）异常，**用例可能带脏数据**，会话收尾会汇总告警 |
| `teardown 汇总` | 会话结束时统计本次有清理失败的用例编号清单 |
| `报告产物脱敏完成：N 个文件已打码` | 会话收尾对报告目录做的**落盘后兜底脱敏**（覆盖第三方插件直接写入的内容） |

查看当天的日志：

```bash
# Windows (Git Bash)
cat "log/$(date +%Y_%m_%d).log"

# 只看请求与关联
grep -E "【请求】|【关联】|<== " "log/$(date +%Y_%m_%d).log"

# 只挑出「带脏数据通过」的用例
grep "teardown 失败" "log/$(date +%Y_%m_%d).log"
```

### 8.5 常用 pytest 参数

| 参数 | 作用 |
| --- | --- |
| `-v` | 显示每条用例名与结果 |
| `-s` | 显示 print 与日志（已默认开启） |
| `-x` | 首个失败即停 |

## 九、MySQL 数据源

### 9.1 启用步骤

**第一步**：准备三张表。

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `test_case_list` | 用例表 | `web`、`port_num`、`url`、`method`、`headers`、`cookies`、`request_body`、`relation`、`expected_code`、`isdel` |
| `test_config` | 配置表 | `web`、`environment`、`value`（通常是接口域名） |
| `test_result_record` | 结果表 | `case_id`、`times`、`response`、`result` |

**第二步**：配置 `config/conf.ini`。

```ini
[run]
data_source = mysql

[db]
host = 127.0.0.1
user = your_user
password = your_password     ; 开源仓库不预置任何真实账号密码
database = your_database
port = 3306
charset = utf8
; 业务标识：对应 test_case_list.web
web = demo_web
; 配置环境：对应 test_config.environment
environment = demo_env
```

> CI 里**不要**把密码写进 `conf.ini`，改用 `AMSAPI_DB_PASSWORD` 从流水线的凭据管理注入。

**第三步**：执行。

```bash
python main.py -m mysql --report allure
```

### 9.2 接口地址拼接规则（沿用原有业务逻辑）

```
完整地址 = test_config.value（配置域名） + ':' + 用例 port_num + 用例 url
```

示例：`http://192.0.2.10` + `:` + `9050` + `/v1/users/login`
→ `http://192.0.2.10:9050/v1/users/login`

| 情况 | 行为 |
| --- | --- |
| 用例 `url` 已是完整地址（http/https 开头） | 直接使用，不再拼接 |
| `port_num` 为空 | 只拼 `域名 + url`（不加冒号） |

### 9.3 与 Excel 数据源的行为差异

| 项 | Excel | MySQL |
| --- | --- | --- |
| 用例范围 | 全部 `isdel=1` 的行 | `web` 匹配且 `isdel=1` 的记录 |
| 地址来源 | 用例自带 url | `test_config` 域名 + `port_num` |
| 结果去向 | Excel 行内 | `test_result_record` 新记录 |
| 执行粒度 | 一条用例 = 一个 pytest 用例 | 整表作为一个 pytest 用例，内部循环（每条为 Allure 步骤） |

### 9.4 相关代码

| 文件 | 职责 |
| --- | --- |
| `utils/mysqlutil.py` | 连接管理（惰性连接）、参数化查询、事务提交/回滚、`with` 语法 |
| `utils/readmysql.py` | 用例读取、配置读取、地址拼接、结果落库 |
| `testcase/test_sql_driver.py` | MySQL 数据驱动用例 |

> `utils/mysqlutil.py` 是**惰性连接**：只导入不连库。
> 因此即使环境没有 MySQL，不启用 mysql 数据源时框架也能正常跑。

## 十、CI/CD 集成

> 本节只讲操作要点。完整方案（含部署后自动触发、参数说明、故障排查）
> 见 **[CI/CD 集成指南](06-CICD集成.md)**。

### 10.1 冒烟测试

部署完成后快速验证核心链路是否可用：

```bash
python main.py --smoke                    # 只跑带 smoke 标签的用例
python main.py --smoke --report allure    # 冒烟 + 报告
```

- 标记方式：Excel 的 `tags` 列、YAML 的 `tags` 字段、手写用例的 `@pytest.mark.smoke`
- 未标记的用例显示为 `deselected`，不参与执行

### 10.2 环境变量覆盖

CI 中**不建议**修改仓库里的 `conf.ini`，用环境变量注入（优先级更高）：

```bash
AMSAPI_ENV=uat AMSAPI_BASE_URL=https://api.example.com \
AMSAPI_WRITE_BACK=false AMSAPI_TIMEOUT=30 python main.py --smoke --report allure
```

变量清单见 [CI/CD 集成 · 环境变量](06-CICD集成.md#三环境变量覆盖ci-的关键能力)。

### 10.3 接入方式

| CI 平台 | 做法 |
| --- | --- |
| Jenkins | 新建 Pipeline 任务，脚本路径填仓库根目录的 `Jenkinsfile` |
| GitLab CI | 参考 [CI/CD 集成 · GitLab](06-CICD集成.md#六gitlab-ci-接入) 的示例配置 |
| GitHub Actions | 参考 [CI/CD 集成 · Actions](06-CICD集成.md#七github-actions-接入) |

退出码：`0` = 全部通过，非 `0` = 有失败/错误（可直接用于流水线判定）。

### 10.4 CI 环境建议

| 项 | 建议 | 原因 |
| --- | --- | --- |
| `write_back` | `false` | 避免改动仓库中的 Excel、避免并发构建冲突 |
| `report_type` | `allure` | 步骤树 + 附件更适合线上排查 |
| `base_url` | 用环境变量注入 | 避免把环境地址提交进仓库 |
| 超时 `timeout` | 调大（如 30） | CI 网络抖动容忍度更高 |
| 本地 HTML 渲染 | 交给流水线插件 | 框架检测到 CI 会自动跳过，节省时间 |
| 数据库密码 | 用 CI 的凭据管理 | **不要把密码写进仓库** |
| **脱敏** | 保持 `mask_sensitive = true` | 制品会被归档转发，明文口令等同外泄 |
| **代理** | 保持 `auto_bypass_proxy = true` | CI 机器多配「出公网」代理，访问内网会报 502 |
| 并行 | `pytest -n auto`（需 `pytest-xdist`） | 缩短全量回归时长 |

### 10.5 CI 前置检查（快速失败）

流水线在跑业务用例**之前**先跑两道门禁，环境/代码问题在 10 秒内暴露，不必等几分钟才发现：

```bash
python -m flake8 .            # ① 静态检查：0 问题才继续
python tools/preflight.py     # ② 环境预检：0 错误才继续
```

`tools/preflight.py` 的参数：

| 参数 | 作用 |
| --- | --- |
| 无 | 常规预检，有警告仍返回 0（本地推荐） |
| `--strict` | 有警告即返回非 0，适合当作流水线硬门禁 |
| `--no-target` | 跳过「目标连通性」检查（被测环境由后续步骤拉起时用） |
| `--json` | 以 JSON 输出，便于流水线解析 |

Runner 已在 `Jenkinsfile` 里新增 `静态检查` 与 `环境预检` 两个 stage；
详见 [CI/CD 集成](06-CICD集成.md)。

## 十一、常见操作场景串联

### 场景：接口变更，需要同步修改

1. 找到接口所属的接口对象：`api/xxx_api.py`
2. 改路径或参数封装
3. 检查用例数据（Excel 的 url/headers/request_body 列，或 YAML）
4. `python main.py -k 相关用例名` 验证
5. 全量回归：`python main.py`

### 场景：新增一个接口的测试

→ 见 [04-开发指南 · 新增接口](04-开发指南.md#一新增接口对象)

### 场景：某条用例失败了，怎么排查

1. 看 Allure 报告 → 找到失败用例 → 看哪一步红了
2. 展开"响应体"附件，看业务状态码与错误信息
3. 若响应体为空/超时 → 看日志的 `请求异常` 行，多半是环境不通
4. 若断言的值不对 → 用 `--collect-only` 确认用例数据是否读对（比如 `${ticket}` 没被替换）
5. 常见原因速查 → [05-常见问题FAQ](05-常见问题FAQ.md)

### 场景：要临时验证一个接口，不想写用例

```bash
python -c "
from api.login_api import LoginApi
api = LoginApi(base_url='http://192.0.2.10:9050')
api.login('demo_user', '密码', '签名')
print(api.code, api.body)
"
```

或直接自测请求工具（需外网，它默认请求 httpbin.org）：

```bash
python -m utils.requestsutil
```
