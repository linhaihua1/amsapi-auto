# 用例编写模板（新手填空版）

> **面向**：第一次给这个框架写接口用例的人。
> **用法**：把本文的模板复制到你的用例文件里，把 `<>` 里的内容换成你系统的真实值即可。
> **配套可复制文件**：`examples/template/`（`api_tables_模板.xlsx` / `demo.yaml` / `README.md`）。
> **上游文档**：列的含义见 [开发指南 · 2.2](04-开发指南.md#22-test_case_list-列含义)，
> 系统差异见 [系统适配指南](08-系统适配指南.md)。

## 一、先选一种数据源（30 秒决定）

| 数据源 | 谁来维护 | 什么时候选它 | 文件位置 |
| --- | --- | --- | --- |
| **Excel** | 业务 / 测试同学 | 需要表格视图、要给人看、不想碰语法 | `data/api_tables.xlsx` 的 `test_case_list` 表 |
| **YAML** | 开发 | 要 diff、要评审、要版本管理、要写注释 | `data/cases/*.yaml` |
| **MySQL** | 多系统共用 | 用例集中管理、多人协作、要落库留痕 | 数据库三张表 |

选好之后在 `config/conf.ini` 里对应写 `data_source = excel | yaml | mysql`。
**不确定就用 Excel**，本文第二节照着填就能跑。

## 二、Excel 模板

### 2.1 最快上手：只填 5 个必填列

打开 `data/api_tables.xlsx` → `test_case_list` 表，第 1 行是表头（**不要改**），
从第 2 行开始一行就是一条用例：

| 列 | 字段 | 填什么 |
| --- | --- | --- |
| **A** | `id` | 用例编号，数字，**不许重复**（例：`1`） |
| **C** | `title` | 用例标题，会出现在报告里（例：`登录并提取票据`） |
| **D** | `url` | 接口地址，**写相对路径**（例：`/v1/users/login`），真实域名由 `base_url` 或档案提供 |
| **E** | `method` | `get` / `post` / `put` / `delete` / `patch` / `head` / `options`（小写） |
| **N** | `isdel` | 固定填 `1` —— 不填 `1` 这条用例**不会被执行**（这是最常见的「写了没跑」原因） |

> 一行 = 一个 pytest 用例。断言失败时报告里显示的就是 `id + title`。

### 2.2 完整模板：四条用例覆盖全部套路

下面四行**可以直接复制进 Excel**（对应 `examples/template/api_tables_模板.xlsx`），
配 `python tools/mock_server.py` 离线就能跑通。
表格里只列了「有值」的列，空白列留空即可。

**① 登录取票（用例 1）** —— 演示请求体、`relation` 提取变量、标签

| 列 | 值 |
| --- | --- |
| A `id` | `1` |
| C `title` | `登录并提取票据` |
| D `url` | `/v1/users/login` |
| E `method` | `get` |
| F `headers` | `{"Content-Type": "application/json"}` |
| H `request_body` | `{"username": "demo_user", "password": "demo_password"}` |
| J `relation` | `ticket=body.data.ticket` |
| K `expected_code` | `200` |
| N `isdel` | `1` |
| O `tags` | `smoke` |
| R `expects` | `type:body.data=dict; not_empty:body.data.ticket` |

> **J 列是参数关联的入口**：`变量名=响应路径`。根是**完整响应**，响应体字段要带 `body.` 前缀。
> 提取出来的 `ticket` 会被后续用例用 `${ticket}` 引用，**不需要写任何代码**。

**② 带依赖 + 参数关联（用例 2）** —— 演示 `${变量}` 注入请求头、`depends`

| 列 | 值 |
| --- | --- |
| A `id` | `2` |
| C `title` | `查询权限点（携带登录票据）` |
| D `url` | `/admin/resource/authority` |
| E `method` | `get` |
| F `headers` | `{"Content-Type": "application/json", "access-ticket": "${ticket}"}` |
| H `request_body` | `{"appCode": "demo-app", "type": "btn"}` |
| K `expected_code` | `200` |
| N `isdel` | `1` |
| O `tags` | `smoke` |
| R `expects` | `type:body.data=list; not_empty:body.data` |
| U `depends` | `1` |

> **U 列 `depends`**：写它依赖的用例 `id`（多个用逗号分隔）。
> 前置用例**没通过时本用例是「跳过」而不是「失败」** —— 前置挂了不代表本用例写错了。
> 这能让 CI 的失败列表干净很多。

**③ 只要断言，不要业务码判定（用例 3）** —— 演示 `check_business`

| 列 | 值 |
| --- | --- |
| A `id` | `3` |
| C `title` | `按 id 查询字典` |
| D `url` | `/dicts` |
| E `method` | `get` |
| H `request_body` | `{"id": "demo-type", "sysCode": "demo"}` |
| K `expected_code` | `200` |
| N `isdel` | `1` |
| R `expects` | `not_empty:body.rows; equals:body.rows.0.id=demo-type` |

> **V 列 `check_business = 0`** 用于「登录令牌、文件下载、健康检查」这类
> **业务码不是标准成功值**的接口，跳过业务码断言，只跑你自己的 `expects`。

**④ 写接口 + 后置清理（用例 4）** —— 演示 `teardown`、`setup`

| 列 | 值 |
| --- | --- |
| A `id` | `4` |
| C `title` | `下单并自动清理` |
| D `url` | `/v1/orders` |
| E `method` | `post` |
| H `request_body` | `{"goodsId": "G0001", "count": 1}` |
| J `relation` | `orderId=body.result.orderId` |
| N `isdel` | `1` |
| R `expects` | `not_empty:body.result.orderId` |
| T `teardown` | `[{"method": "post", "url": "/v1/orders/cancel", "request_body": {"orderId": "${orderId}"}}]` |
| V `check_business` | `0` |

> **T 列 `teardown` 的语义：断言失败也会执行**，用来清理在对方系统里造出来的脏数据。
> **S 列 `setup`** 语法相同，用来造前置数据。
> 四个样例的完整 JSON 见 `examples/template/api_tables_模板.xlsx` 的对应单元格。

### 2.3 格式细节（写错就静默失效）

| 列 | 正确 | 错误 |
| --- | --- | --- |
| F `headers` / G `cookies` / H `request_body` | **合法 JSON 字符串**：`{"a": 1}` | `a=1`、单引号 `{'a': 1}` |
| O `tags` | 逗号分隔：`smoke,core` | `[smoke]` |
| S `setup` / T `teardown` | JSON **数组**：`[{"method": "post", ...}]` | 单个对象（要包一层 `[]`） |
| R `expects` | 分号分隔多条：`gt:body.total=0; not_empty:body.rows` | 逗号分隔 |
| N `isdel` | `1` | `true` / `是` / 空 |

> B `time` / L `response` / M `ispass` 三列由框架**自动回写**，不要手工填。
> 想关掉回写：`conf.ini` 的 `write_back = false`（CI 推荐）。

## 三、YAML 模板（可直接复制）

存成 `data/cases/<模块名>.yaml`。文件名**按字母序加载**，但 `depends` 会自动把
被依赖的用例提到前面（框架内部已排序），所以**不用靠文件名去凑顺序**。

```yaml
# =====================================================================
# <模块名> 用例（YAML 数据源）
# ---------------------------------------------------------------------
# 与 Excel 一一对应：Excel 是「列」，YAML 是「字段」。
# 相对路径 + ${变量} + expects 的写法完全一致。
# =====================================================================
cases:
  # ---------------- ① 登录取票：演示 relation 提取变量 ----------------
  - id: 1001
    title: 登录并提取票据
    tags: [ smoke ]                     # 参与 CI 冒烟筛选
    url: /v1/users/login                # 相对路径，域名由 AMSAPI_BASE_URL / 档案提供
    method: get
    headers:
      Content-Type: application/json
    request_body:                       # GET 会自动挂到 query 参数上，无需区分 params/json
      username: demo_user
      password: demo_password
    relation: ticket=body.data.ticket   # 提取进变量池，后续写 ${ticket} 即可
    expected_code: 200
    expects: "type:body.data=dict; not_empty:body.data.ticket"

  # ---------------- ② 带依赖 + 参数关联：演示 depends 与 ${ticket} ----------------
  - id: 1002
    title: 查询权限点（携带登录票据）
    tags: [ smoke ]
    url: /admin/resource/authority
    method: get
    headers:
      Content-Type: application/json
      access-ticket: ${ticket}          # 每次请求前从变量池实时解析
    request_body: { "appCode": "demo-app", "type": "btn" }
    depends: 1001                       # 前置未通过 -> 本用例 skip（不是 fail）
    expected_code: 200
    expects: "type:body.data=list; not_empty:body.data; elapsed=3000"

  # ---------------- ③ 分页断言：演示数值比较与列表下标路径 ----------------
  - id: 1003
    title: 分页查询组织树
    url: /admin/org/getTreeRootParentCodePage
    method: get
    headers: { "Content-Type": "application/json", "access-ticket": "${ticket}" }
    request_body:
      page: 1
      size: 20
      code: demo-org
    depends: 1001
    expected_code: 200
    expects: "gt:body.total=0; not_empty:body.rows; equals:body.rows.0.code=demo-org-1"

  # ---------------- ④ 写接口 + 后置清理：演示 relation + teardown ----------------
  - id: 1004
    title: 下单并自动清理
    url: /v1/orders
    method: post
    request_body: { "goodsId": "G0001", "count": 1 }
    relation: orderId=body.result.orderId
    check_business: false               # 业务码非标准成功值，只看下面的 expects
    teardown:                           # 断言失败也会执行
      - method: post
        url: /v1/orders/cancel
        request_body: { "orderId": "${orderId}" }
    expects: "not_empty:body.result.orderId"
```

> **想只跑这个文件？** `AMSAPI_CASES_DIR=data/cases python main.py -m yaml`
> 或直接 `python main.py -k id1001` 按用例编号跑单条。

## 四、栏位速查表（Excel 列 ↔ YAML 字段）

| 列 | YAML 字段 | 必填 | 一句话说明 |
| --- | --- | --- | --- |
| A `id` | `id` | 是 | 用例编号，`depends` 靠它引用 |
| B `time` | — | — | 回写：执行时间 |
| C `title` | `title` | 是 | 报告里的用例名 |
| D `url` | `url` | 是 | 相对路径 / 完整地址 / `别名:/路径`，支持 `${var}` |
| E `method` | `method` | 是 | 7 种 HTTP 方法，小写 |
| F `headers` | `headers` | 否 | JSON，支持 `${var}` |
| G `cookies` | `cookies` | 否 | JSON |
| H `request_body` | `request_body` | 否 | JSON（XML 系统可直接放 XML 原文），支持 `${var}` |
| I `request_type` | `request_type` | 否 | 兼容列，Q 列优先 |
| J `relation` | `relation` | 否 | `变量=响应路径`，多个逗号分隔 |
| K `expected_code` | `expected_code` | 视档案 | `status`/`code` 风格必填；`success`/`errno` 风格可留空 |
| L `response` | — | — | 回写：响应内容 |
| M `ispass` | — | — | 回写：是否通过 |
| N `isdel` | `isdel` | 是 | `1` = 执行 |
| O `tags` | `tags` | 否 | 逗号分隔，CI 冒烟筛选用 |
| P `host` | `host` | 否 | 域名别名（网关 + 多微服务系统） |
| Q `content_type` | `content_type` | 否 | 覆盖默认请求体类型 |
| R `expects` | `expects` | 否 | 字段级断言（21 种算子） |
| S `setup` | `setup` | 否 | 前置造数据，JSON 数组 |
| T `teardown` | `teardown` | 否 | 后置清理，JSON 数组，**失败也执行** |
| U `depends` | `depends` | 否 | 依赖的用例 id，多个逗号分隔 |
| V `check_business` | `check_business` | 否 | `0` = 不做业务码断言（默认 `1`） |

## 五、21 种断言算子（写在 `expects` 里）

写法：`算子:路径=期望值`，多条用 `;` 分隔；无期望值的算子可省略 `=值`。

| 类别 | 算子 | 例子 |
| --- | --- | --- |
| 相等 | `equals` / `not_equals` | `equals:body.status=200` |
| 包含 | `contains` / `not_contains` | `contains:body.msg=成功` |
| 前后缀 / 正则 | `startswith` / `endswith` / `regex` | `regex:body.data.id=^ORD-` |
| 类型 | `type` | `type:body.data=list`（`str/int/float/bool/list/dict/none/number`） |
| 存在性 | `exists` / `not_exists` | `exists:body.data.total` |
| 集合 | `in` / `not_in` | `in:body.data.status=CREATED,PAID` |
| 数值 | `gt` / `ge` / `lt` / `le` | `gt:body.total=0` |
| 长度 | `length` | `length:body.rows=1` |
| 空 / 非空 | `empty` / `not_empty` | `not_empty:body.data.ticket` |
| 性能 | `elapsed` | `elapsed=3000`（毫秒） |
| 结构 | `schema` | `schema:body={"type":"object"}`（需 `jsonschema`） |

> **路径规则**：根是**完整响应**。所以 `body.` 开头指响应体，
> `code` 指 HTTP 状态码（`equals:code=200`），也支持列表下标 `body.rows.0.id`。
> 算子名写错时，报错信息会列出全部可用算子。

## 六、参数关联（接口之间怎么传值）

```
① 上游用例：relation: ticket=body.data.ticket     ← 提取，写进全局变量池
② 下游用例：headers / url / request_body 里写 ${ticket}   ← 引用，每次请求前实时解析
③ 跨用例依赖：depends: 1001                        ← 保证①比②先跑
```

三条一起用才是完整的「登录取票 → 携带票据」链路。只要缺第 ③ 条，
用例执行顺序就没有保证（可能先跑②，那时 `${ticket}` 还不存在）。

**找不到变量时的表现**：`${ticket}` 会原样保留发给服务端，
上游接口连不上/断言失败时，下游会因 `depends` 被 skip，不会报一堆误导性的失败。

## 七、写完用例后的自查清单

- [ ] `id` 唯一，`isdel = 1`（Excel）
- [ ] `url` 是相对路径（或确实需要完整地址），域名走 `base_url` / 档案 / `AMSAPI_BASE_URL`
- [ ] `method` 小写，且与接口实际方法一致
- [ ] `headers` / `request_body` 是**合法 JSON**（用 JSON 校验器过一遍）
- [ ] 要跨用例传值：上游写了 `relation`，下游写了 `${var}`，下游写了 `depends`
- [ ] 断言至少有一条（只判 HTTP 200 等于没验业务）
- [ ] 写接口配了 `teardown` 清理
- [ ] 想进冒烟集：`tags` 里加 `smoke`
- [ ] 本地跑通：`python main.py -k id<用例编号>`（**不要用中文关键字**，pytest 会转义 nodeid）

## 八、常见错误对照表

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 写了用例但没被执行 | `isdel` 不是 `1`；或 `data_source` 选了别的数据源 | 填 `1`；查 `conf.ini` 的 `data_source`，或命令行 `-m` 指定 |
| `${ticket}` 原样发给了服务端 | 上游 `relation` 没写 / 没跑成功 / 缺 `depends` | 补齐 `relation` 与 `depends` |
| 下游一堆失败，全是因为登录挂了 | 没写 `depends` | 加 `depends: <登录用例 id>` |
| `expects` 报「未知算子」 | 算子名拼错 | 报错信息里有完整算子清单，见本文第五节 |
| 业务码断言失败，但接口其实没问题 | 该接口业务码不是标准成功值 | 设 `check_business = 0` |
| 报「Excel 用例文件不存在」 | 路径/环境变量没配好 | 看报错里的 `AMSAPI_EXCEL_FILE` / `AMSAPI_DATA_DIR` 指引 |
| 数据源选 `mysql` 却整体跳过 | `[db]` 段没配 | 填 `host/user/password/database`，或注入 `AMSAPI_DB_*` |
| 第二次跑 `--report html` 异常 | 已修复（`--html=` 等号连写） | 升级到本版本；见 `CHANGELOG.md` |
